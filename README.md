# 💰 SpendDNA — Personal Spending Analyzer

**SpendDNA** is a Python-based financial transaction analysis project that converts raw transaction data into structured spending insights.

The project uses **Pandas and NumPy** to clean transaction data, identify vendors, categorize expenses, analyze spending patterns, detect unusual transactions, and generate spending-behavior archetypes.

> **Note:** The archetypes generated by this project are rule-based and intended for educational/fun analysis. They are not financial advice or professional financial assessments.

---

## 📌 Project Overview

Bank transaction statements can contain hundreds of transactions with inconsistent descriptions, dates, amount formats, and transaction types.

SpendDNA processes this raw data and produces a simplified report answering questions such as:

* How much money came in?
* How much money was spent?
* What is the net change?
* What is the savings rate?
* Which categories receive the most spending?
* Which vendors receive the most money?
* How does spending change across months?
* At what times of the day does spending occur?
* How much food delivery happens late at night?
* Which transactions are unusually large?
* What spending patterns describe the user?

## ✨ Features

### 🧹 1. Data Cleaning

The project cleans the raw transaction dataset by:

* Converting transaction dates into datetime format
* Removing currency symbols such as `₹` and `Rs.`
* Removing commas from amounts
* Converting amounts into numerical values
* Standardizing transaction types
* Removing duplicate transactions
* Removing rows with invalid dates or amounts

Example:

```text
₹1,250.00
```

is converted into:

```text
1250.00
```

## 💰 4. Financial Summary

SpendDNA calculates:

* Total credits
* Total debits
* Net change
* Savings rate
* Total transactions
* Number of unique vendors

The savings rate is calculated as:

```text
Savings Rate = (Total Credits - Total Debits) / Total Credits × 100
```

## 🚨 10. Anomaly Detection

The project uses a **z-score based approach** to identify unusually large transactions within each spending category.

The calculation is based on:

```text
z = (value - category mean) / category standard deviation
```

Transactions with:

```text
z > 2
```

are treated as potential anomalies.

The report displays up to the top five detected anomalies along with:

* Date
* Vendor
* Category
* Amount
* Z-score

# 🎭 Spending Archetypes

SpendDNA includes a rule-based system that identifies spending patterns.

### 🍔 The Foodie

Assigned when combined spending on:

* Food Delivery
* Restaurants
* Cafes

is greater than **25%** of total spending.

---

### 📦 The Quick Commerce Junkie

Assigned when Quick Commerce spending exceeds **15%** of total spending.

---

### 🛍️ The Shopaholic

Assigned when E-commerce spending exceeds **15%** of total spending.

---

### 📈 The Investor

Assigned when Investment spending exceeds **15%** of total spending.

---

### 🌙 The Late-Night Snacker

Assigned when more than **50%** of food-delivery transactions occur between:

```text
21:00 and 02:00
```

---

### 🚕 The Cab Commuter

Assigned when Transport spending exceeds **10%** of total spending.

---

### 📺 The Subscription Lover

Assigned when the user has subscriptions with at least **5 different vendors**.

---

### 🎉 The YOLO Spender

Assigned when the calculated savings rate is below **10%**.

---

### 💰 The Disciplined Saver

Assigned when the calculated savings rate is above **40%**.

# ⚠️ Limitations

This project has some limitations:

1. **Vendor identification is keyword-based.**
   New or differently formatted transaction descriptions may remain uncategorized.

2. **Categories are manually defined.**
   The project uses a predefined vendor-to-category mapping.

3. **Anomaly detection is basic.**
   The current approach uses category-level z-scores and should not be treated as a complete fraud-detection system.

4. **Archetypes are rule-based.**
   They are based on predefined spending thresholds and are intended for educational/fun analysis.

5. **The project is designed around the structure of the provided transaction dataset.**
   Other bank statement formats may require modifications.
